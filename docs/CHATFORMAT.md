# 对话转换器规格（自包含版）

> **本文件是自包含的。** 依据它就能为一个新平台从头写出转换器，不需要任何其它资料、对话或代码。
>
> 适用任务：把某平台的「对话导出 JSON」转换成 AfterChat 可读的 Markdown / ZIP。

---

## 0. 任务定义

| | 输入 | 输出 |
|---|---|---|
| 单个对话 | 一份 JSON | 一份 `.md` |
| 一次导出含多个对话 | 一份 JSON | 一个 `.zip`，内含多份 `.md` |

平台差异只体现在**「怎么从 JSON 里找出对话、消息、角色、时间」**。
**输出的 Markdown 与打包格式对所有平台完全一致** —— 也就是本文件第 1～7 节的内容，必须逐字遵守。

> 小提示：很多平台的「导出」是一个 zip，里面才是 `data.json`（路径和层级不固定，可能带 BOM）。
> 建议**直接从压缩包里读**该文件，不要落地解压 —— 不依赖 `powershell` / `unzip` / `ditto`，
> 也没有 zip 路径穿越风险。UTF-8 BOM 记得剥掉。

---

## 1. 物理约束

- 扩展名：`.md`
- 编码：UTF-8（**允许 BOM**，读取时应剥掉）
- 换行：`LF` 或 `CRLF` 均可
- 缩进：不强制

---

## 2. 文件结构骨架

```markdown
## Metadata

- **Model:** `模型名`
- **Time:** 2026-09-17 21:19:12 +08:00
- **URL:** https://平台地址/对话id

## Conversation

### ⚙️ System

（系统提示词，可选；没有就整段省略）

### 🧑‍💻 User

用户说的话……

### 🤖 Assistant

#### 🤔 Thought Process

（思维链，可选）

#### 💡 Response

助手正式回复……
```

---

## 3. Metadata 区

位置：`## Conversation` **之前**。

| 键 | 格式 | 说明 |
|---|---|---|
| `Model` | `` - **Model:** `模型名` `` | **必须用反引号包裹**，见下方警告 |
| `Time` | `- **Time:** 2026-09-17 21:19:12 +08:00` | 本地时间，`YYYY-MM-DD HH:mm:ss ±HH:MM`，**不要反引号** |
| `URL` | `- **URL:** https://…` | 没有就省略 |

> ⚠️ **`Model` 的格式必须精确。** 读取方用它做正则提取：
> `/- \*\*Model:\*\* `(.*?)`/`
> 多一个空格、少一个反引号都会导致模型信息丢失。

- 除 `Model` 外都不强制。**允许追加平台特有的键**（例如 `- **Topic ID:** `x``、`- **Assistant:** `y``），
  排在推荐键之后即可，读取方会忽略不认识的键。
- 可以在 Metadata 里再加 `### 小节`，但**不要把消息内容写在这里** —— 正文一律放 `## Conversation` 之后。
- 时间取「对话自身的时间」，不要用「转换发生的当下」。

---

## 4. Conversation 正文区

### 4.1 分隔行

必须有且只有一行 `## Conversation`。

### 4.2 角色头（精确字符串，不要改）

| 角色 | 标题行 |
|---|---|
| 用户 | `### 🧑‍💻 User` |
| 助手 | `### 🤖 Assistant` |
| 系统提示 | `### ⚙️ System` |
| 无法识别的角色 | 一律兜底成 `### 🤖 Assistant` |

- 消息体范围 = **当前角色头 → 下一个角色头之间**的文本。
- 顺序必须与原始对话时间顺序一致。
- 空消息（没有可导出内容）**整条跳过**，不要留一个孤立的角色头。
- 系统提示词是**对话的第一条消息**，排在首个用户/助手消息之前。

> ⚠️ 读取方用 `^###\s+.*\b(User|Assistant)\b.*$` 找角色边界。
> 所以正文里绝不允许出现未被处理的 `###` 行（见第 5 节）—— 否则包含 `User`/`Assistant` 单词的
> 正文标题会被误判成新消息，把一条消息劈成两半。这条既是格式要求，也是正确性要求。

### 4.3 思维链 / 回复

助手消息按内容类型拆成两段，**每段只出一个标题**（多个思维块合并到同一个标题下）：

```markdown
### 🤖 Assistant

#### 🤔 Thought Process

（思维链内容）

#### 💡 Response

（正式回复内容）
```

- 标题文字**必须完全一致**，不要加空格、不要改 emoji。
- **标题后面必须空一行**再写内容。
  - ❌ `#### 💡 Response正文直接贴上来`（第 2 节说的错误就是这个）
  - ✅ `#### 💡 Response` + 空行 + 正文
- 没有思维链时，不要输出 `#### 🤔 Thought Process`，正文直接跟在角色头后面。
- 只有思维链、没有回复时，只输出思维链段，不要输出空的 `#### 💡 Response`。
- 两段内容各自内部多个片段用 `\n\n` 连接。

## 5. 消息体规则（**最容易做错的一节**）

### 5.1 井号标题 → 加粗

正文里的 `#` `##` `###` … 标题行，**必须转成加粗**：

```
# 一级标题        →  **一级标题**
### 1. 基本构成   →  **1. 基本构成**
```

**精确规则**（逐行处理，行首必须是列 0 的 `#`）：

> 本规则**只作用于消息体内容**。`## Metadata`、`### Run Settings`、`## Conversation`、
> 角色头 `### 🧑‍💻 User`…、以及 `#### 🤔 Thought Process` / `#### 💡 Response`
> 都是**转换器自己产出的结构标题**，不要拿它们去过这个函数。

1. 匹配 `^#{1,6}\s+(.+)$`（`#` 之后必须有至少一个空白字符，再至少一个非空字符）。
2. 让 `inner = 匹配到的内容.trim()`；若 `inner` 为空，整行原样保留。
3. 输出 `**` + `inner` + `**`。

不匹配的例子：`####### 七个井号`（超过 6 个）、`#紧贴文字`（`#` 后无空白）、`# `（无内容）。

### 5.2 整条标题加粗：吸收内层 `**`

如果标题文本**自己就含 `**`**，直接外包一层会产生同级定界符交错，CommonMark 会错配，
结果是「只有某个词被强调」甚至**残留可见的星号**：

```
## 方案一：**“水珠胶囊”——像吃水果一样喝水**
   ❌  **方案一：**“水珠胶囊”——像吃水果一样喝水****     ← 渲染出可见星号
   ✅  **方案一：“水珠胶囊”——像吃水果一样喝水**          ← 整条加粗
```

**做法**：在包裹之前，把标题文本里**不在行内代码中**的 `**` 全部删掉。
整条标题都已经加粗了，内层加粗本来就是冗余的。

**但行内代码里的 `**` 不能删** —— 那不是强调，是内容：

```
# 匹配 `**/*.js` 的路径   →  **匹配 `**/*.js` 的路径**     ✅
                              **匹配 `/*.js` 的路径**      ❌ 破坏了 glob
```

行内代码的界定用 CommonMark 规则：**N 个反引号开始，同样 N 个反引号结束**。

### 5.3 三种必须原样保留的 `#`

| 情形 | 例子 | 处理 |
|---|---|---|
| **围栏代码块内** | ` ```python ` … `# 注释`… ` ``` ` | 原样保留 |
| **缩进代码块** | `    # 缩进 4 空格` | 原样保留（不是列 0 的 `#`） |
| **行内代码内** | `` `# not a heading` `` | 原样保留 |

围栏用 ``` 或 ~~~ 都可以，**按类型配对**（``` 只能被 ``` 关闭，不能被 ~~~ 关闭）。
围栏标记本身可以带前导空格；语言标注（` ```python `）不影响判断。

> 宁可漏转、不可误改：把代码里的 `#` 改成加粗是**破坏内容**，把标题漏转只是**少一层强调**。
> 所以围栏/缩进的判断要偏保守。

### 5.4 不要动的东西

- 保留原 Markdown：列表、引用、表格、链接、普通加粗/斜体、行内代码
- 不要重新排版、不要 trim 每行
- 不要转义、不要 HTML 转义

**参考实现（伪代码）**：

```
function strip_hashes(text):
    fence = null                      # null / "```" / "~~~"
    for line in text.split("\n"):
        marker = "```" if line.trim_start().starts_with("```")
                 else "~~~" if line.trim_start().starts_with("~~~")
                 else null
        if fence != null:             # 围栏内：原样输出
            output(line)
            if marker == fence: fence = null
        elif marker != null:          # 围栏开始
            fence = marker; output(line)
        else:
            output(strip_one_line(line))   # 见下

function strip_one_line(line):
    n = count of leading '#' in line      # 必须从列 0 开始数
    if n == 0 or n > 6: return line
    rest = line[n:]
    if rest is empty or rest[0] is not whitespace: return line
    inner = rest.trim()
    if inner is empty: return line
    return "**" + remove_bold_outside_code(inner).trim() + "**"

function remove_bold_outside_code(text):
    out = ""; open_ticks = 0; i = 0
    while i < len(text):
        if text[i] == '`':
            run = count of consecutive '`' at i
            if open_ticks == 0: open_ticks = run
            elif open_ticks == run: open_ticks = 0
            out += text[i : i+run]; i += run
        elif open_ticks == 0 and text[i:i+2] == "**":
            i += 2                      # 吸收掉
        else:
            out += text[i]; i += 1
    return out
```

## 6. 打包规则

### 6.1 单条

一份 `.md`，文件名 = 对话标题。

### 6.2 多条

一个 zip：

```
chat-export-{platform}-all-{毫秒时间戳}.zip
```

- `{platform}`：平台短名，小写字母（如 `qwen`、`cherry`、`m365`）
- `{毫秒时间戳}`：生成时刻的 Unix 毫秒

**zip 内条目名**：

```
{YYYYMMDD-HHmmss}-{标题}.md          ← 单层，无目录
platform/{YYYYMMDD-HHmmss}-{标题}.md  ← 或按平台自定义分组目录
```

- 时间取**对话时间**，不是导出时间；包内按时间**从旧到新**排列。
- 没有可用时间时，用零填充序号兜底（如 `001-标题.md`）。
- 条目名重复时追加 `-2`、`-3`（扩展名保持在末尾）。
- 建议用 Deflate 压缩。
- 条目自身的修改时间应设为**对话时间**。
  > zip 的 DOS 时间戳只有 **2 秒精度**，秒数会被向下取偶，与真实时间可能差 ≤1 秒，这是格式限制。
  >
  > `export-failures.md` 不是某个对话，用**当前时间**即可。

### 6.3 失败报告

若有对话**完全无法导出**，zip 内额外放一份 `export-failures.md`，记录标题、ID 和原因。
没有任何失败时不要生成这个文件。

## 7. 标题 → 文件名

- 去掉 Windows 非法字符：`\ / * ? : " < > |` ，以及 `\r` `\n` `\t`
- `trim()` 后为空 → 用兜底名（如 `Untitled`、`Untitled_Conversation`）
- 建议限制长度（条目名 60～80 字符）
- **不要**在这里做 HTML/Markdown 转义

## 8. 自检清单

写完转换器后，用下面的用例自查（全部应通过）。
先确认这份文档**不依赖任何其它文件**就能写出全部逻辑。

### 8.1 `#` 转加粗

| 输入 | 期望输出 |
|---|---|
| `# Title` | `**Title**` |
| `### Deep` | `**Deep**` |
| `# 1. **重点**` | `**1. 重点**` |
| `## 方案一：**“水珠”——像吃水果**` | `**方案一：“水珠”——像吃水果**` |
| `# 🌅 **早晨**` | `**🌅 早晨**` |
| `# 1. **A** 2. **B**` | `**1. A 2. B**` |
| `# **Bold**` | `**Bold**` |
| `# a *b* c` | `**a *b* c**`（单星号斜体保留） |
| `# 匹配 `**/*.js` 的路径` | `**匹配 `**/*.js` 的路径**` |
| `####### 七个井号` | 原样 |
| `#紧贴文字` | 原样 |
| `# ` | 原样 |

### 8.2 代码保护

```
 ```python            →   内容原样，`# 注释` 不变
 # 注释
 ```
```

```
 输入含 `    # 缩进四格`  →   原样（缩进代码块）
```

### 8.3 整条加粗

对 8.1 每个**已转换**的输出，再加一条断言：

> 结果以 `**` 开头、以 `**` 结尾，且**中间不再出现 `**`**
> （行内代码段之内的 `**` 除外）。

这条断言不需要 Markdown 渲染器就能验证，且它正是「整条标题被强调、无可见星号」的充要条件。

### 8.4 渲染验证（有条件时）

用 CommonMark 渲染器（如 JS 的 `markdown-it`、Python 的 `markdown-it-py`）渲染后检查：

1. 最外层 `<strong>` 覆盖全部可见文本
2. 去掉 `<code>…</code>` 后，可见文本里没有残留的 `*`

### 8.5 结构验证

对每份产出的 `.md` 断言：

- 以 `## Metadata` 开头
- 存在 `- **Model:** `…``（含反引号）
- `Time` 匹配 `^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2} [+-]\d{2}:\d{2}$`
- 存在 `## Conversation`
- `#### 💡 Response` 与 `#### 🤔 Thought Process` **独占一行**（后面不能直接跟正文）
- 正文里（围栏外、列 0）没有残留的 `^#{1,6}\s+\S` 行，角色头与 `#### 🤔`/`#### 💡` 除外

## 9. 常见坑

| 坑 | 后果 |
|---|---|
| `#### 💡 Response` 与正文贴在同一行 | 读取方把整行当无内容的标题，搜索结果无法定位 |
| 正文 `#` 标题没转加粗 | 违反契约；含 `User`/`Assistant` 的标题还会**把消息劈成两半** |
| 标题内层 `**` 没吸收 | 渲染出可见星号，强调不全 |
| 把行内代码里的 `**` 也删了 | 破坏 glob 等代码内容 |
| 把围栏内 `#` 也转了 | 破坏 Python/Shell 代码 |
| `Model` 少了反引号 | 读取方提取不到模型名 |
| 用当前时间而非对话时间 | 时间线错乱，按时间归档失效 |
| 空消息也输出角色头 | 产生空消息气泡 |
| UTF-8 BOM 未剥 | JSON 解析失败 |
| zip 里条目重名 | 后一个覆盖前一个 |
