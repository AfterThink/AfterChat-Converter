# ChatFormat 规范契约

> 本规范完整定义了 AfterChat 对话导出的 Markdown 与 ZIP 打包格式标准，供各平台转换器实现参考。
>
> 适用场景：将各平台的对话备份数据（JSON / SQLite / ZIP）转换为统一规范的 AfterChat Markdown 与 ZIP 归档包。

---

## 0. 任务定义

| | 输入 | 输出 |
|---|---|---|
| 单个会话 | 单个 JSON 文件 | 单个 `.md` 文件 |
| 批量导出（含多个会话） | 单个 JSON 文件 / 压缩包 | 单个 `.zip` 文件（内含多个 `.md`） |

各平台的差异仅存在于**输入数据的解析逻辑**（提取会话、消息体、角色及时间戳）。
**输出的 Markdown 格式与打包规范对所有平台完全统一**，转换器实现必须严格遵循第 1 至第 7 节的规范。

> **输入读取建议**：部分平台的导出产物为内含数据文件的 ZIP 压缩包（路径层级不固定且可能包含 BOM）。
> 建议直接在内存或流式读取压缩包内部条目，避免解压到磁盘，以提升处理性能并规避路径遍历等安全风险。若包含 UTF-8 BOM 须主动剔除。

---

## 1. 物理约束

- 扩展名：`.md`
- 编码：UTF-8（**允许 BOM**，读取时应剥掉）
- 换行：`LF` 或 `CRLF` 均可
- 缩进：不强制

---

## 2. 文件结构骨架

```markdown
## Metadata

- **Model:** `模型名`
- **Time:** 2026-09-17 21:19:12 +08:00
- **URL:** https://平台地址/对话id

## Conversation

### ⚙️ System

（系统提示词，可选；没有就整段省略）

### 🧑‍💻 User

用户说的话……

### 🤖 Assistant

#### 🤔 Thought Process

（思维链，可选）

#### 💡 Response

助手正式回复……
```

---

## 3. Metadata 区

位置：`## Conversation` **之前**。

| 键 | 格式 | 说明 |
|---|---|---|
| `Model` | `` - **Model:** `模型名` `` | **必须用反引号包裹**，见下方警告 |
| `Time` | `- **Time:** 2026-09-17 21:19:12 +08:00` | 本地时间，`YYYY-MM-DD HH:mm:ss ±HH:MM`，**不要反引号** |
| `URL` | `- **URL:** https://…` | 没有就省略 |

> ⚠️ **`Model` 的格式必须精确。** 读取方用它做正则提取：
> `/- \*\*Model:\*\* `(.*?)`/`
> 多一个空格、少一个反引号都会导致模型信息丢失。

- 除 `Model` 必填外，其余字段均为可选。**允许追加平台特有的扩展键**（例如 `- **Topic ID:** `x``、`- **Assistant:** `y``），建议置于标准键之后；解析端会忽略未知键。
- Metadata 区域内可添加 `### 小节`，但**严禁包含消息正文**；正文必须置于 `## Conversation` 之后。
- 时间戳须取会话自身的实际发生时间，不得使用转换执行时的系统时间。

---

## 4. Conversation 正文区

### 4.1 分隔行

必须有且只有一行 `## Conversation`。

### 4.2 角色头（精确字符串，不要改）

| 角色 | 标题行 |
|---|---|
| 用户 | `### 🧑‍💻 User` |
| 助手 | `### 🤖 Assistant` |
| 系统提示 | `### ⚙️ System` |
| 无法识别的角色 | 一律兜底成 `### 🤖 Assistant` |

- 消息体范围 = **当前角色头 → 下一个角色头之间**的文本。
- 顺序必须与原始对话时间顺序一致。
- 无有效内容的空消息须**直接跳过**，避免生成孤立的角色标题。
- 系统提示词（System Prompt）作为**对话的首条消息**输出，位于首个用户或助手消息之前。

> ⚠️ 解析端通过正则表达式 `^###\s+.*\b(User|Assistant)\b.*$` 识别角色边界。
> 因此正文内部严禁出现未经转换的 `###` 行（参见第 5 节）；否则包含 `User` 或 `Assistant` 单词的正文标题会被误判为新的消息分块，导致消息截断。

### 4.3 思维链 / 回复

助手消息按内容类型拆成两段，**每段只出一个标题**（多个思维块合并到同一个标题下）：

```markdown
### 🤖 Assistant

#### 🤔 Thought Process

（思维链内容）

#### 💡 Response

（正式回复内容）
```

- 标题文字**必须完全一致**，不要加空格、不要改 emoji。
- **标题后面必须空一行**再写内容。
  - ❌ `#### 💡 Response正文直接贴上来`（第 2 节说的错误就是这个）
  - ✅ `#### 💡 Response` + 空行 + 正文
- 没有思维链时，不要输出 `#### 🤔 Thought Process`，正文直接跟在角色头后面。
- 只有思维链、没有回复时，只输出思维链段，不要输出空的 `#### 💡 Response`。
- 两段内容各自内部多个片段用 `\n\n` 连接。

## 5. 消息体转换规则

### 5.1 标题语法转换（`#` 转换为加粗）

正文里的 `#` `##` `###` … 标题行，**必须转成加粗**：

```
# 一级标题        →  **一级标题**
### 1. 基本构成   →  **1. 基本构成**
```

**精确规则**（逐行处理，行首必须是列 0 的 `#`）：

> 本规则**只作用于消息体内容**。`## Metadata`、`### Run Settings`、`## Conversation`、
> 角色头 `### 🧑‍💻 User`…、以及 `#### 🤔 Thought Process` / `#### 💡 Response`
> 都是**转换器自己产出的结构标题**，不要拿它们去过这个函数。

1. 匹配 `^#{1,6}\s+(.+)$`（`#` 之后必须有至少一个空白字符，再至少一个非空字符）。
2. 让 `inner = 匹配到的内容.trim()`；若 `inner` 为空，整行原样保留。
3. 输出 `**` + `inner` + `**`。

不匹配的例子：`####### 七个井号`（超过 6 个）、`#紧贴文字`（`#` 后无空白）、`# `（无内容）。

### 5.2 标题内层加粗吸收

若原始标题文本中已包含 `**` 加粗标记，直接在外层包裹加粗会导致 CommonMark 定界符错配，产生局部强调异常或**残留可见星号**：

```
## 方案一：**“水珠胶囊”——像吃水果一样喝水**
   ❌  **方案一：**“水珠胶囊”——像吃水果一样喝水****     ← 产生可见多余星号
   ✅  **方案一：“水珠胶囊”——像吃水果一样喝水**          ← 规范整条加粗
```

**转换策略**：在外层包裹 `**` 之前，移除标题内容中**所有处于行内代码段外部**的 `**` 标记。因整行标题已置于加粗中，内层加粗属于冗余样式。

**注意：必须保留行内代码内部的 `**`**（此情况为内容本身而非强调标记，如 glob 语法）：

```
# 匹配 `**/*.js` 的路径   →  **匹配 `**/*.js` 的路径**     ✅
                              **匹配 `/*.js` 的路径**      ❌ 破坏了 glob
```

行内代码的界定用 CommonMark 规则：**N 个反引号开始，同样 N 个反引号结束**。

### 5.3 须保持原样的 `#` 场景

| 场景 | 示例 | 处理方式 |
|---|---|---|
| **围栏代码块内部** | ` ```python ` … `# 注释`… ` ``` ` | 保持原样 |
| **缩进代码块** | `    # 缩进 4 空格` | 保持原样（非行首第 0 列的 `#`） |
| **行内代码内部** | `` `# not a heading` `` | 保持原样 |

代码围栏支持使用 ``` 或 ~~~，须**成对匹配**（``` 仅能由 ``` 闭合，无法由 ~~~ 闭合）。
围栏标记允许包含前导空格；语言标注（如 ` ```python `）不影响匹配逻辑。

> **实现原则**：严禁误改代码块内的字符。将代码中的 `#` 误转为加粗属于破坏性变更，因此对代码围栏与缩进块的识别策略应采取保守判定。

### 5.4 内容完整性约束

- 保持 Markdown 原始排版：列表、引用、表格、链接、常规加粗/斜体及行内代码等均保持原样；
- 禁止对正文各行进行无意义的重排或全局 `trim`；
- 禁止引入额外的字符转义或 HTML 实体转义。

**参考实现（伪代码）**：

```
function strip_hashes(text):
    fence = null                      # null / "```" / "~~~"
    for line in text.split("\n"):
        marker = "```" if line.trim_start().starts_with("```")
                 else "~~~" if line.trim_start().starts_with("~~~")
                 else null
        if fence != null:             # 围栏内：原样输出
            output(line)
            if marker == fence: fence = null
        elif marker != null:          # 围栏开始
            fence = marker; output(line)
        else:
            output(strip_one_line(line))   # 见下

function strip_one_line(line):
    n = count of leading '#' in line      # 必须从列 0 开始数
    if n == 0 or n > 6: return line
    rest = line[n:]
    if rest is empty or rest[0] is not whitespace: return line
    inner = rest.trim()
    if inner is empty: return line
    return "**" + remove_bold_outside_code(inner).trim() + "**"

function remove_bold_outside_code(text):
    out = ""; open_ticks = 0; i = 0
    while i < len(text):
        if text[i] == '`':
            run = count of consecutive '`' at i
            if open_ticks == 0: open_ticks = run
            elif open_ticks == run: open_ticks = 0
            out += text[i : i+run]; i += run
        elif open_ticks == 0 and text[i:i+2] == "**":
            i += 2                      # 吸收掉
        else:
            out += text[i]; i += 1
    return out
```

## 6. 打包规则

### 6.1 单条

一份 `.md`，文件名 = 对话标题。

### 6.2 多条

一个 zip：

```
chat-export-{platform}-all-{毫秒时间戳}.zip
```

- `{platform}`：平台短名，小写字母（如 `qwen`、`cherry`、`m365`）
- `{毫秒时间戳}`：生成时刻的 Unix 毫秒

**zip 内条目名**：

```
{YYYYMMDD-HHmmss}-{标题}.md          ← 单层，无目录
platform/{YYYYMMDD-HHmmss}-{标题}.md  ← 或按平台自定义分组目录
```

- 时间取**对话时间**，不是导出时间；包内按时间**从旧到新**排列。
- 没有可用时间时，用零填充序号兜底（如 `001-标题.md`）。
- 条目名重复时追加 `-2`、`-3`（扩展名保持在末尾）。
- 建议用 Deflate 压缩。
- 条目自身的修改时间应设为**对话时间**。
  > zip 的 DOS 时间戳只有 **2 秒精度**，秒数会被向下取偶，与真实时间可能差 ≤1 秒，这是格式限制。
  >
  > `export-failures.md` 不是某个对话，用**当前时间**即可。

### 6.3 失败报告

若有对话**完全无法导出**，zip 内额外放一份 `export-failures.md`，记录标题、ID 和原因。
没有任何失败时不要生成这个文件。

---

## 7. 标题 → 文件名

- 去掉 Windows 非法字符：`\ / * ? : " < > |` ，以及 `\r` `\n` `\t`
- `trim()` 后为空 → 用兜底名（如 `Untitled`、`Untitled_Conversation`）
- 建议限制长度（条目名 60～80 字符）
- **不要**在这里做 HTML/Markdown 转义

| `# ` | 原样 |

### 8.2 代码保护

```
 ```python            →   内容原样，`# 注释` 不变
 # 注释
 ```
```

```
 输入含 `    # 缩进四格`  →   原样（缩进代码块）
```

### 8.3 整条加粗

对 8.1 每个**已转换**的输出，再加一条断言：

> 结果以 `**` 开头、以 `**` 结尾，且**中间不再出现 `**`**
> （行内代码段之内的 `**` 除外）。

这条断言不需要 Markdown 渲染器就能验证，且它正是「整条标题被强调、无可见星号」的充要条件。

### 8.4 渲染验证（有条件时）

用 CommonMark 渲染器（如 JS 的 `markdown-it`、Python 的 `markdown-it-py`）渲染后检查：

1. 最外层 `<strong>` 覆盖全部可见文本
2. 去掉 `<code>…</code>` 后，可见文本里没有残留的 `*`

### 8.5 结构验证

对每份产出的 `.md` 断言：

- 以 `## Metadata` 开头
- 存在 `- **Model:** `…``（含反引号）
- `Time` 匹配 `^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2} [+-]\d{2}:\d{2}$`
- 存在 `## Conversation`
- `#### 💡 Response` 与 `#### 🤔 Thought Process` **独占一行**（后面不能直接跟正文）
- 正文里（围栏外、列 0）没有残留的 `^#{1,6}\s+\S` 行，角色头与 `#### 🤔`/`#### 💡` 除外

## 9. 注意事项与边界条件

| 场景 | 影响 |
|---|---|
| `#### 💡 Response` 标记后未换行 | 解析端将整行视为无内容的标题，导致内容索引与定位失败 |
| 正文 `#` 标题未转换为加粗 | 违反格式规范；若标题包含 `User`/`Assistant` 等关键字会导致消息被截断拆分 |
| 标题内层 `**` 未被吸收 | 渲染时出现多余星号且样式解析不全 |
| 误删行内代码中的 `**` | 破坏 glob 路径或代码原有语义 |
| 误转换代码围栏内的 `#` | 破坏 Python/Shell 等脚本注释语法 |
| `Model` 字段遗漏反引号 | 解析端无法准确通过正则提取模型名称 |
| 采用当前系统时间而非会话时间 | 时间线排序错乱，基于时间的归档功能失效 |
| 空消息输出孤立角色头 | 产生无有效内容的空白消息气泡 |
| 未剔除 UTF-8 BOM | 导致部分 JSON 反序列化库解析失败 |
| ZIP 内部条目重名未处理 | 导致同名文件被覆盖丢失 |
