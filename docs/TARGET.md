# 桌面端交互设计目标与规格

## 核心设计原则

1.  **即时响应 (Immediacy)**：操作即触发结果。核心交互模型为“拖放文件即执行”，省去冗余的确认或提交按钮。
2.  **单一焦点 (Single Focus)**：界面聚焦于文件拖拽放置区，所有周边元素均作为辅助状态反馈或配置项。
3.  **克制反馈 (Restrained Feedback)**：界面状态迁移清晰平滑，通过微动效、状态图标与文本明确传达处理进度（就绪、处理中、成功、失败），避免过度的视觉干扰。

## 用户交互流程与状态机

应用界面遵循明确的单向状态迁移模型：

1.  **就绪状态 (Ready)**
    *   窗口中心呈现拖拽放置区域，显示引导提示（如“拖入备份文件或文件夹”）；
    *   底部提供输出路径配置项：“保存在原文件同级目录”，默认勾选。

2.  **文件悬停状态 (Hovering)**
    *   文件拖入窗口上方时，放置区域高亮提示，表明可接收拖放。

3.  **文件置入与处理流程 (Processing Flow)**
    *   用户松开鼠标后立即开始处理流程：
    *   **分支 A：默认输出路径（复选框已勾选）**
        *   接收输入文件；
        *   界面进入“处理中”状态（展示加载动画）；
        *   前端根据文件名匹配或后端自动尝试调用对应的 Sidecar 二进制；
        *   后端执行完毕并返回结果。
    *   **分支 B：自定义输出路径（复选框未勾选）**
        *   接收输入文件；
        *   调用原生文件保存对话框，由用户选择保存目录；
        *   用户确认目录后，界面进入“处理中”状态；
        *   前端传递 `-o` 参数调用 Sidecar；
        *   后端执行完毕并返回结果。

4.  **完成状态 (Completed)**
    *   结束加载状态，呈现处理结果：
        *   **成功**：显示成功提示，并提供“在文件管理器中定位”链接；
        *   **失败**：显示明确的错误信息及详细日志查看入口；
    *   完成状态在数秒后或用户进行下一次拖拽时自动重置为**就绪状态**。

## 组件与交互规范

*   **拖拽放置区**
    *   作为界面的核心交互主体；
    *   在不同状态（Ready、Hovering、Processing、Completed）下呈现对应的视觉表现；
    *   Ready 状态展示应用图标与操作指引；
    *   Processing 状态展示非确定性进度指示器；
    *   Completed 状态展示结果图标与状态摘要。

*   **输出路径选项**
    *   表现为复选框及标签文本：“保存在原文件同级目录”；
    *   默认处于勾选状态；
    *   设置状态持久化保存在本地；
    *   其勾选状态决定文件拖入后的流程分支，点击时仅切换选项状态，不触发额外动作。

*   **状态反馈文本**
    *   位于拖拽区域下方的次要文本区；
    *   用于呈现当前处理的文件名称、匹配的转换器标识或执行结果摘要。

## Sidecar 调用与文件路由

*   **调用时机**：文件置入且输出路径确定后触发；
*   **路由策略**：前端根据输入文件名特征预判目标转换器，无法精确匹配时交由后端按序轮询探测：
    *   文件名包含 `cherry` -> 调用 `cherry`；
    *   文件名包含 `qwen` -> 调用 `qwen`；
    *   文件名包含 `claude` -> 调用 `claude`；
    *   文件名包含 `rikka` -> 调用 `rikka`；
    *   其他情况（如包含 JSON 的文件夹或无显著特征的文件） -> 默认调用 `ai-studio` 或进入轮询；
*   **参数组装**：
    *   输入路径：传入文件的绝对路径；
    *   输出路径：若指定了自定义路径，通过 `-o` 选项传递；否则不传，依赖转换器默认的同目录输出策略。

## 视觉规范与动效指导

*   **过渡动效**：状态切换采用 150ms～250ms 的淡入淡出或轻微位移动画，保证交互响应的敏捷感；
*   **色彩体系**：中性灰度作为基底，强调色用于可交互部件与成功状态，警示色用于异常与错误反馈；
*   **排版**：严格遵循字体层级与留白节奏，保持紧凑、清爽的桌面工具体验。

## 技术约束

1.  **架构基础**：Tauri 桌面端应用；
2.  **进程通信**：通过 Tauri Process API 调用 `bin/` 目录下的 Sidecar 二进制，保持转换器与 GUI 的松耦合；
3.  **平台兼容**：保持代码在 Windows 平台上的稳定运行，兼顾跨平台通用规范。
